## 1. Data

All transformer splits share the schema `cleaned_text, toxic` where
`toxic ∈ {0, 1}`. The Naive Bayes deep-cleaned splits may have additional
preprocessing columns — see `../CODE/naive_bayes/data_pipeline.py`.

### 1.1 `train.csv` / `val.csv` / `test.csv` — the "6w" splits

| Split | N | Toxic % |
|---|---:|---:|
| train | 60 000 | 9.2 % |
| val   |  7 500 | 9.2 % |
| test  |  7 500 | 9.2 % |

Built from a **light cleaning** of the public
[Jigsaw Toxic Comment Classification](https://www.kaggle.com/c/jigsaw-toxic-comment-classification-challenge)
and
[Civil Comments](https://huggingface.co/datasets/google/civil_comments)
datasets — only obvious noise stripped; punctuation, emoji and casing kept
so transformer tokenisers can leverage the full context. Multi-label
toxicity is collapsed to a binary target: `toxic = 1` iff **any**
sub-category (`toxic`, `severe_toxic`, `obscene`, `threat`, `insult`,
`identity_hate`) is positive.

### 1.2 `train_deepclean.csv` / `test_deepclean.csv` — Naive Bayes splits

Same rows as the light-cleaning splits, but additionally lowercased,
punctuation-stripped, stop-word-removed and lemmatised (NLTK). These are
the exact files `baseline_model.ipynb` reads; a bag-of-words model needs
aggressive normalisation to keep the feature space tractable.

### 1.3 `manual_annotation_200.csv` — team-labelled OOD set (Part B, 20 cr.)

232 comments, drawn from two sources: a stratified sample of 150 rows
from the 100 k merged Jigsaw + Civil Comments pool (labels discarded
before annotation and removed from the training pool to avoid leakage),
plus 82 fresh comments collected from Reddit, Instagram, YouTube, and
X. Each comment was independently labelled by two annotators. Cohen's κ
improved from **0.40** on the first pass to **0.73** after a
guideline-refinement round — substantial agreement, with the remaining
disagreements concentrated on implicit / sarcastic toxicity (the hardest
cases for every model; see Part D qualitative analysis).

Full annotation protocol, round-by-round κ computation, and final set
composition are documented in `annotation_process.md` in this folder.

Toxic class proportion: **37.9 %** (88 / 232), substantially higher than
the training distribution — this is intentional, to stress-test the
models on OOD content.

> **Evaluation usage:** every model in the main results table is
> evaluated on the **full 232 rows** of this file. The only exception is
> the BERT-aug ablation, which trained on 174 of the 232 rows and is
> therefore evaluated on the remaining 58 — see the top-level README
> §4 and the report §Ablation for why those numbers are not directly
> comparable.

## 2. Outputs

Every model has its own `outputs/<model>/` subfolder. To regenerate any
of them, re-run the corresponding notebook in `../CODE/<model>/`.

The `outputs/comparison/` subfolder is populated by
`../CODE/evaluate_all.py` once all four models' weights are installed.

## 3. Model weights

Naive Bayes weights (≈ 26 MB total) are **bundled directly** inside
`saved_model/naive_bayes/` — still comfortably under the 200 MB Moodle limit. The four transformer checkpoints each exceed
the 200 MB Moodle limit and are therefore hosted on OneDrive — see
`saved_model/README.md` for the per-model links and extraction paths.
